## Задача 1. Механика ленты советов (ядро Фазы 2)

**Проблема.** Сейчас каждый тап/свайп — это `fetchAdvices({ limit: 1 })`, отдельный сетевой
запрос (`src/hooks/useAdvice.ts:38`). При этом:

- API отдаёт батчи до 40 советов за один запрос — сайт работает именно батчами;
- истории на сервере нет → свайп «назад» возможен только через локальный кэш (зафиксировано
  в `AGENTS.md`), а сейчас `onSwipeLeft` и `onSwipeRight` делают одно и то же
  (`AdviceScreen.tsx:25-27`);
- дедуп по `id` обязателен (рандом отдаёт повторы) — его нет;
- нет защиты от гонок: быстрые свайпы порождают параллельные запросы, и более ранний ответ
  может перезаписать более поздний;
- при ошибке `setAdvice(null)` — показанный совет пропадает, экран мигает загрузкой.

**Что делаем (в `useAdvice`, без новых зависимостей):**

1. Загрузка батчем: `fetchAdvices({ limit: N })`, N в пределах `MAX_BATCH_SIZE` (подобрать,
   ориентир — 10–20; сервер отдаёт ≤40). Полученные советы кладём в локальную очередь.
2. Дедуп по `id`: множество показанных id; повторы из батча отбрасываются. Если после
   фильтрации батч пуст — запросить следующий.
3. История: массив показанных советов + индекс текущего. Свайп вправо (или влево — направление
   определить в UI-решении) = шаг назад по истории без сети; свайп вперёд = следующий из
   очереди/истории, при исчерпании — новый батч.
4. Защита от гонок: счётчик запросов (применять ответ только последнего вызова) либо
   `AbortController` на предыдущий запрос. Плюс игнорирование жестов, пока идёт загрузка
   и очередь пуста.
5. Ошибки: не стирать текущий совет при сбое обновления — показать ошибку поверх/рядом,
   совет остаётся. Стейт загрузки не должен мигать «Loading…» при наличии контента.
6. Предзагрузка фоновых картинок для следующих 1–2 советов очереди (`Image.prefetch`),
   а не только для текущего.

**Критерии приёмки:**

- Тап/свайп вперёд при непустой очереди не делает сетевого запроса.
- Свайп назад возвращает ровно предыдущий совет (с его фоном) без сети.
- Повторный совет с тем же `id` не показывается дважды.
- 10 быстрых свайпов подряд не приводят к «перескоку» на устаревший ответ.
- При выключенной сети текущий совет остаётся на экране, показывается сообщение об ошибке.

## Задача 3. ⚠️ ОТКРЫТОЕ РЕШЕНИЕ: жестовая логика в `AdviceCard` — требует обсуждения

презентация») ставил критерий приёмки «`AdviceCard` не содержит `PanResponder`»: вся жестовая

`src/components/AdviceCard/AdviceCard.tsx:51-122`, а `AdviceScreen` — тонкая обёртка над

## Задача 4. Техдолг (мелкий, независимый)

1. **Дубль HTTP-кода**: `fetchDefaultBgImages` (`src/api/advice.ts:431-522`) повторяет ~90 строк
   `requestJsonOnce` (таймаут, relayAbort, content-type, обёртка ошибок) — и без ретраев.
   Вынести общий хелпер: `requestJson` с флагом «ответ не v2-конверт» либо отдельный
   `requestRawJson`, который используют обе функции.
2. **Смещённый shuffle**: `sort(() => Math.random() - 0.5)` в `src/utils/resolveAdviceImage.ts:56`
   даёт неравномерное распределение. Заменить на выбор случайного тега индексом
   (как `randomFrom`) без перемешивания.
3. **`App.tsx` нарушает конвенцию стилей**: инлайн `StyleSheet.create` (`App.tsx:25-29`),
   а правило — стили в `<Component>.style.ts`. Вынести.
4. **Дубль логики в `useAdvice`**: prefetch + обработка ошибок продублированы между эффектом
   инициализации и `fetchNewAdvice` (`useAdvice.ts:35-60` и `97-124`). После задачи 1 код
   всё равно перепишется — дубль уйдёт в общий «загрузчик батча».
5. **UI-строки на английском**: `Loading advice...`, `No advice available` в `AdviceCard.tsx`,
   тогда как конвенция — русский. Перевести.
